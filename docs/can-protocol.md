# 夹爪控制板 CAN 协议 V1.2

更新日期：2026-11-10。适用固件：GD32F503KEU7 claw_ctrl。
本协议覆盖补光灯设置和控制板主动心跳；原有巨蟹电机协议保持不变。

## 1. 总线与报文约定

| 项目 | 约定 |
|---|---|
| CAN 控制器 | CAN0，ISO CAN FD |
| 标识符 | 标准 11 位 ID，IDE=0 |
| 帧类型 | 数据帧，非远程帧 |
| 仲裁段/数据段速率 | 均为 1 Mbps |
| BRS | 关闭（0） |
| 数据长度 | 固定 8 字节（CAN DLC 编码也为 8） |
| 多字节字段 | 无符号、小端序，低字节在前 |
| 补光灯 PWM | PA6 / TIMER2_CH0，5 kHz，高有效，设置值 0～1000 |

| CAN ID（十六进制） | 方向 | 用途 |
|---|---|---|
| `0x220` | 主控 → 控制板 | 设置补光灯亮度 |
| `0x221` | 控制板 → 主控 | 周期心跳与调光后的状态快照 |

ID 是总线仲裁标识，不是 MCU 引脚号。当前按总线上一块控制板设计；没有节点地址或广播字段。
若接入多块控制板，必须事先重新分配各板 ID，避免它们使用相同发送 ID。当前 ID 不与本工程已使用的电机 ID 重叠，整机仍需统一管理总线 ID。
不定义应用层 CRC、序号或专用 ACK，使用 CAN 自身校验；CAN 硬件 ACK 不等同于本板执行成功。

## 2. 补光灯设置帧：0x220

| 字节 | 字段 | 类型 / 合法值 |
|---|---|---|
| Byte 0 | 协议版本 | `0x01` |
| Byte 1 | 命令 | `0x01`：设置 PWM 亮度 |
| Byte 2 | 亮度低字节 | uint16 小端，范围 0～1000 |
| Byte 3 | 亮度高字节 | 同上 |
| Byte 4～7 | 保留 | 必须全部为 `0x00` |

解析公式：`level = data[2] | (data[3] << 8)`。
占空比 = `level / 1000`；0 为关闭，1000 为全亮。这里的亮度是 PWM 占空比，不保证与视觉亮度线性对应。

当前 PA6 直接驱动 TX6128 DIM，采用数字 PWM 调光：低电平约 0 V，高电平约 3.3 V，周期 200 μs；非零设置值 1～1000 对应请求占空比 0.1%～100%，不设模拟电压偏置。图片中的 1.1～3.1 V / 1%～100% 表属于模拟调光，不能直接作为当前 PWM 占空比的限幅或查表依据。非法帧不会开启灯光或改变已有设置。

当前 TIMER2 输入时钟 252 MHz，PSC=0、ARR=50399，比较值为 `round(level * 50400 / 1000)`；0 时 CCR=0，1000 时 CCR=50400，持续高电平。PWM 比较值由预装载在更新点生效。驱动内部响应延迟会影响极小占空比的实际电流，最小可靠亮度需要实板测量；CAN 数值及心跳仍表示请求值。

依据：[TX612X 厂家调光应用说明](https://www.xdssemi.com/uploadfile/2024/0806/20240806180747345.pdf) 第 6～7 页，直接 PWM 调光频率建议为 500 Hz～5 kHz，且调光精度受开关频率与 PWM 频率比例影响。

| 操作 | ID | 8 字节数据（十六进制） |
|---|---|---|
| 关闭 | `0x220` | `01 01 00 00 00 00 00 00` |
| 25% | `0x220` | `01 01 FA 00 00 00 00 00` |
| 50% | `0x220` | `01 01 F4 01 00 00 00 00` |
| 100% | `0x220` | `01 01 E8 03 00 00 00 00` |

### 接收和执行规则

1. 只接受标准 ID `0x220`、CAN FD、8 字节数据帧。主控须关闭 BRS。
2. 校验版本、命令、保留字节和亮度范围；校验全部通过后更新目标 PWM，非零亮度通过一阶低通逐步更新实际 PWM。
3. 亮度大于 1000 时整帧拒绝，**不会在协议层截断为 1000**。
4. 非法帧不改变原亮度，不触发即时状态上报，也不发送错误应答；周期心跳继续。
5. 每一帧合法命令执行后，立即尝试将一帧 `0x221` 入发送队列，回报已接受的目标值。非零目标约每 10ms 平滑更新；目标 0 立即写比较值 0，正常在随后一个 PWM 周期（200 μs）以内关灯。
6. 重复命令是幂等的：同一亮度重复设置不会累计变化，每次合法命令仍触发一次状态上报。
7. 亮度保持至下一条合法命令或 MCU 复位；不写入 Flash，上电/复位默认关闭。
8. 主控失联后保持最后设置值，本协议没有主控 → 控制板的心跳，因此不执行“主控失联自动关灯”。

## 3. 心跳/状态帧：0x221

| 字节 | 字段 | 定义 |
|---|---|---|
| Byte 0 | 协议版本 | `0x01` |
| Byte 1 | 电机汇总状态 | 见下表 |
| Byte 2～3 | 目标 PWM 设置值 | uint16，小端，0～1000 |
| Byte 4～7 | MCU 运行时间 | uint32，小端，单位 ms，来自板级毫秒时基 |

| Byte 1 | 电机汇总状态 | 含义 |
|---|---|---|
| `0x00` | OFF | 指示关闭状态，保留与内部状态机的一致映射；当前正常运行流程通常不产生此值 |
| `0x01` | DISABLED | 尚未收到完整反馈、未就绪或未全部使能 |
| `0x02` | NORMAL | 两台电机均正常且已使能 |
| `0x03` | UPGRADE | 正处于检测到的电机升级会话 |
| `0x04` | FAULT | 至少一台电机报告故障或已建立通信后的反馈超时 |

状态沿用现有双电机状态机：故障优先于升级，升级优先于普通未就绪/正常状态。
从未收到反馈的电机为未就绪；正常建立反馈后断开超过 1500 ms 才产生反馈超时故障。升级会话中的超时处理沿用现有电机逻辑。
电机状态不等于控制板自身故障码；即使电机断开，控制板仍主动发送心跳。
PWM 字段是已接受的目标设置值，不是滤波过程中的瞬时占空比，也不是电流、灯珠发光或光学亮度的测量结果。非零亮度变化采用约 100ms 时间常数的一阶低通，约 0.3s 接近目标变化量的 95%；关闭绕过滤波。

示例：两台电机正常、补光灯 50%、MCU 运行 10 秒：

```text
ID = 0x221
DATA = 01 02 F4 01 10 27 00 00
```

其中 `F4 01` = 500，`10 27 00 00` = 10000 ms。

### 发送时序

- CAN 初始化成功后启动协议任务；第一帧周期心跳在任务启动约 500 ms 后发送。
- 此后每 500 ms 由主循环尝试发送一帧。实际发送时间受主循环、发送队列和 CAN 仲裁影响。
- 合法 `0x220` 命令额外触发即时状态帧，不重置周期心跳计时；命令恰好落在周期点时允许连续两帧状态。
- 主循环较长时间未执行时只补发当前一帧，不追赶所有错过的周期，避免恢复后突发上报。
- TX 队列满时丢弃本次状态上报，不等待、不在下一次循环忙重试；下一个周期继续尝试。合法调光命令已经执行，不会因状态帧入队失败而回滚。
- 当前 CAN 驱动关闭自动重发；发送入队不保证最终到达主控。Bus-Off 或物理总线异常时主控可能收不到心跳，恢复后再次按周期尝试。
- 心跳不在 SysTick 中断中发送；主循环停止工作时周期心跳也停止。CAN 初始化失败时无法发送心跳。

## 4. 主控端处理建议

1. 只接收并解析标准 CAN FD `0x221`、8 字节、版本 `0x01` 的状态帧。
2. 用**主控本地时钟**记录最近合法状态帧的接收时间，周期帧与即时帧均刷新在线时间。
3. 连续 1500 ms 未收到合法状态帧，判定控制板失联；收到后恢复在线。启动后尚未收到首帧时为“未确认在线”。
4. 下发亮度后等待新的状态帧，核对 Byte 2～3 与期望值是否一致；如未收到或不一致，可以重发同一条设置命令。
5. 不把状态帧当作带请求序号的事务 ACK：它是当前快照，协议不提供请求与回复的一一对应关系。
6. MCU 运行时间约 49.7 天按 uint32 回绕。相邻时间差用无符号减法计算；时间变小不能单独作为重启的充分证据。
7. 控制板失联时是否停止电机或采取其他动作，由主控整机策略决定；控制板端默认保持补光灯设置。

主机打包/解析字段的 Python 示例（不绑定具体 USB-CAN 设备 API）：

```python
import struct

def light_payload(level: int) -> bytes:
    if not 0 <= level <= 1000:
        raise ValueError("level must be 0..1000")
    return struct.pack("<BBH4x", 1, 1, level)

def parse_status(data: bytes):
    if len(data) != 8 or data[0] != 1:
        raise ValueError("invalid status frame")
    version, motor_state, level, uptime_ms = struct.unpack("<BBHI", data)
    if motor_state > 4 or level > 1000:
        raise ValueError("invalid status fields")
    return motor_state, level, uptime_ms
```

发送时另外指定 CAN ID `0x220`、标准帧、FD=1、BRS=0；接收前另行确认 CAN ID/格式。

## 5. 与原有功能的关系

- `0x220` 已加入 CAN0 硬件精确匹配滤波器，沿用 RX 队列后在主循环解析，不在 CAN 中断操作灯效。
- `0x221` 仅用于发送，不加入本板接收滤波器。
- 调光命令不计作电机控制活动，不会抑制原有主控空闲后的 `0x80` 电机同步查询。
- 心跳和指示灯使用同一电机汇总状态；周期上报前更新电机超时判断。
- 此功能不实现电机升级传输或 MCU bootloader。

CAN ID、版本字节 0x01 和报文布局不变；新增非零亮度平滑，0x221 的亮度字段明确为目标值，保持主控即时核对功能。参数与库适配见 `m_middlewares/PORTING.md`。

## V1.2 说明

补光灯 PWM 从 1 kHz 改为 5 kHz。按现有 PA6 直连 DIM 的硬件保留 0～1000 占空比语义，0 为立即关闭，非零有效值平滑调光；不使用模拟调光表映射。CAN ID、版本字节和报文布局保持不变。
