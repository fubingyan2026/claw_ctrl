# 夹爪控制板 CAN 协议 V1.3

更新日期：2026-11-13。适用固件：GD32F503KEU7 claw_ctrl。
本协议覆盖补光灯设置和控制板状态查询。

## 版本记录

| 版本 | 变更 |
|---|---|
| V1.3 | 取消定时心跳。在 `0x220` 增加查询命令 `0x00`，查询和调光均通过 `0x221` 返回电机状态、目标亮度和 MCU 时间戳。 |
| V1.2 | 补光灯 PWM 从 1 kHz 提高到 5 kHz，保留 0～1000 的占空比设置。 |
| V1.1 | 新增非零亮度平滑调节，明确 `0x221` 的亮度字段为目标值。参数与库适配见 [中间件移植说明](../m_middlewares/PORTING.md)。 |

## 1. 总线与报文约定

| 项目 | 约定 |
|---|---|
| CAN 控制器 | CAN0，ISO CAN FD |
| 标识符 | 标准 11 位 ID，IDE=0 |
| 帧类型 | 数据帧，非远程帧 |
| 仲裁段/数据段速率 | 均为 1 Mbps |
| BRS | 关闭（0） |
| 数据长度 | 固定 8 字节（CAN DLC 编码也为 8） |
| 多字节字段 | 无符号、小端序，低字节在前 |
| 补光灯 PWM | PA6 / TIMER2_CH0，5 kHz，高有效，设置值 0～1000 |

| CAN ID（十六进制） | 方向 | 用途 |
|---|---|---|
| `0x220` | 主控 → 控制板 | 查询状态或设置补光灯亮度 |
| `0x221` | 控制板 → 主控 | 返回当前状态和 MCU 时间戳 |

ID 是总线仲裁标识，不是 MCU 引脚号。当前按总线上一块控制板设计；没有节点地址或广播字段。
若接入多块控制板，必须事先重新分配各板 ID，避免它们使用相同发送 ID。当前 ID 不与本工程已使用的电机 ID 重叠，整机仍需统一管理总线 ID。
不定义应用层 CRC、序号或专用 ACK，使用 CAN 自身校验；CAN 硬件 ACK 不等同于本板执行成功。

## 2. 请求帧 `0x220`

| 字节 | 字段 | 类型 / 合法值 |
|---|---|---|
| Byte 0 | 协议版本 | `0x01` |
| Byte 1 | 命令 | `0x00` 查询状态，`0x01` 设置 PWM 亮度 |
| Byte 2～3 | 亮度 | 设置时为 uint16 小端，范围 0～1000，对应 0～180 mA。查询时忽略，发送端可填零 |
| Byte 4～7 | 保留 | 必须全部为 `0x00` |

解析公式：`level = data[2] | (data[3] << 8)`。
占空比 = `level / 1000`；0 为关闭，1000 为全亮。这里的亮度是 PWM 占空比，不保证与视觉亮度线性对应。

当前 PA6 直接驱动 TX6128 DIM，采用数字 PWM 调光：低电平约 0 V，高电平约 3.3 V，周期 200 μs；非零设置值 1～1000 对应请求占空比 0.1%～100%，不设模拟电压偏置。图片中的 1.1～3.1 V / 1%～100% 表属于模拟调光，不能直接作为当前 PWM 占空比的限幅或查表依据。非法帧不会开启灯光或改变已有设置。

当前 TIMER2 输入时钟 252 MHz，PSC=0、ARR=50399，比较值为 `round(level * 50400 / 1000)`；0 时 CCR=0，1000 时 CCR=50400，持续高电平。PWM 比较值由预装载在更新点生效。驱动内部响应延迟会影响极小占空比的实际电流，最小可靠亮度需要实板测量；CAN 状态回复表示请求值。

依据：[TX612X 厂家调光应用说明](https://www.xdssemi.com/uploadfile/2024/0806/20240806180747345.pdf) 第 6～7 页，直接 PWM 调光频率建议为 500 Hz～5 kHz，且调光精度受开关频率与 PWM 频率比例影响。

| 操作 | ID | 8 字节数据（十六进制） |
|---|---|---|
| 查询状态 | `0x220` | `01 00 00 00 00 00 00 00` |
| 关闭 | `0x220` | `01 01 00 00 00 00 00 00` |
| 25% | `0x220` | `01 01 FA 00 00 00 00 00` |
| 50% | `0x220` | `01 01 F4 01 00 00 00 00` |
| 100% | `0x220` | `01 01 E8 03 00 00 00 00` |

### 接收和执行规则

1. 只接受标准 ID `0x220`、CAN FD、8 字节数据帧。主控须关闭 BRS。
2. 查询状态时保持当前输出，回复一帧 `0x221`。
3. 设置时校验亮度范围，更新目标后回复一帧 `0x221`。非零目标约每 10 ms 平滑更新，目标 0 立即写比较值 0。
4. 重复设置同一目标时继续当前输出和平滑过程，并回复一次当前状态。
5. 帧格式、长度、版本、命令、保留字节或设置亮度非法时，控制板保持原输出且不回复。
6. 上电默认关闭。查询中断或主控失联时保持最后设置值。CAN 升级时，Boot 和新 App 接续当前 PWM 占空比与调光目标。

## 3. 状态回复 `0x221`

控制板每次处理合法请求时重新获取 MCU 毫秒时间戳，并组装当前状态回复。

| 字节 | 字段 | 定义 |
|---|---|---|
| Byte 0 | 协议版本 | `0x01` |
| Byte 1 | 电机汇总状态 | 见下表 |
| Byte 2～3 | 目标 PWM 设置值 | uint16，小端，0～1000 |
| Byte 4～7 | MCU 运行时间 | uint32，小端，单位 ms，来自板级毫秒时基 |

| Byte 1 | 电机汇总状态 | 含义 |
|---|---|---|
| `0x00` | OFF | 指示关闭状态，保留与内部状态机的一致映射；当前正常运行流程通常不产生此值 |
| `0x01` | DISABLED | 等待首帧反馈，或两台均已检测到但尚未全部使能 |
| `0x02` | NORMAL | 两台电机均正常且已使能 |
| `0x03` | UPGRADE | 正处于检测到的电机升级会话 |
| `0x04` | FAULT | 任一台电机报告故障、反馈超时，或只检测到一台电机 |

状态沿用现有双电机状态机：故障优先于升级，升级优先于普通未就绪/正常状态。
从电机服务初始化或该电机最近一次有效反馈起，超过 1000 ms 未收到有效反馈即报超时故障。收到第一台电机的有效反馈后，若另一台尚未反馈，下一次状态判定即进入故障。两台均恢复有效反馈后，按实际状态重新判定。电机升级会话期间暂停反馈超时判定。
即使两台电机均断开，控制板也会应答查询，并在超时后报告电机故障。
PWM 字段是已接受的目标设置值，不是滤波过程中的瞬时占空比，也不是电流、灯珠发光或光学亮度的测量结果。非零亮度变化采用约 100ms 时间常数的一阶低通，约 0.3s 接近目标变化量的 95%；关闭绕过滤波。

### 完整收发示例

以下两组请求和回复均使用标准 11 位 ID、CAN FD 数据帧、DLC=8、BRS=0，仲裁段和数据段均为 1 Mbps。

| 步骤 | 方向 | CAN ID | 8 字节数据 |
|---|---|---|---|
| 设置补光灯为 50% | 主控 → 控制板 | `0x220` | `01 01 F4 01 00 00 00 00` |
| 回复设置后的状态 | 控制板 → 主控 | `0x221` | `01 02 F4 01 10 27 00 00` |
| 查询当前状态和时间戳 | 主控 → 控制板 | `0x220` | `01 00 00 00 00 00 00 00` |
| 回复查询时的状态 | 控制板 → 主控 | `0x221` | `01 02 F4 01 74 27 00 00` |

示例回复中，`01` 是协议版本，`02` 表示两台电机正常且已使能，`F4 01` 表示目标亮度 500（50%），`10 27 00 00` 表示 MCU 运行时间 10000 ms。亮度和时间戳均为小端序。

查询发生在 100 ms 后，因此第二次回复的时间戳 `74 27 00 00` 表示 10100 ms。只读取当前状态时，发送表中的查询命令即可。

### 发送时序

- `0x221` 仅响应合法的 `0x220` 请求。
- 主循环处理请求并尝试将回复放入发送队列。实际发出时间受队列和 CAN 仲裁影响。
- 队列满时丢弃该次回复。CAN 驱动关闭自动重发，主控超时后可重发请求。

## 4. 主控端处理建议

1. 按需发送 `0x220` 查询或调光请求，接收标准 CAN FD `0x221`、8 字节、版本 `0x01` 的回复。
2. 用主控本地时钟从发送请求开始计时。CANable 插件等待 1500 ms，收到合法回复后显示快照及回复时间，未收到则显示回复超时。
3. 核对调光结果时，比较设置请求的回复 Byte 2～3 与期望亮度。
4. 回复是当前状态快照，协议无请求序号。主控需要关联回复时，应等待上一条请求收到回复或超时后再发送。
5. MCU 运行时间约 49.7 天按 uint32 回绕。相邻时间差用无符号减法计算。

主机打包/解析字段的 Python 示例（不绑定具体 USB-CAN 设备 API）：

```python
import struct

def light_payload(level: int) -> bytes:
    if not 0 <= level <= 1000:
        raise ValueError("level must be 0..1000")
    return struct.pack("<BBH4x", 1, 1, level)

status_query_payload = bytes.fromhex("01 00 00 00 00 00 00 00")

def parse_status(data: bytes):
    if len(data) != 8 or data[0] != 1:
        raise ValueError("invalid status frame")
    version, motor_state, level, uptime_ms = struct.unpack("<BBHI", data)
    if motor_state > 4 or level > 1000:
        raise ValueError("invalid status fields")
    return motor_state, level, uptime_ms
```

发送亮度设置和状态查询时均使用 ID `0x220`、标准帧、FD=1、BRS=0。接收时确认 ID `0x221` 和帧格式。

## 5. 与原有功能的关系

- `0x220` 加入 CAN0 硬件精确匹配滤波器，由主循环解析 RX 队列。
- `0x221` 仅用于发送，不加入本板接收滤波器。
- 调光和状态查询不计作电机控制活动。主控空闲时仍发送 `0x080` 电机同步查询。
- 回复前更新电机超时判断。夹爪板升级期间，指示灯优先显示蓝色，状态回复仍返回电机汇总状态。
- 夹爪板升级使用 `0x703/0x704`，详见 [CAN 升级与烧录](firmware-upgrade.md)。
